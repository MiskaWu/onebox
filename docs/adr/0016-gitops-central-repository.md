# 0016. GitOps with Argo CD: one central repository, the gate on the CI bump, one project per tenant

- Status: Accepted
- Related: [0001](0001-one-host-per-environment-one-repository.md), [0009](0009-guarded-irreversible-changes.md), [0012](0012-datastore-reachability.md), [0017](0017-openbao-and-external-secrets.md), [0018](0018-one-oidc-issuer.md)

## Context

Teams deploy their services to the cluster and need review, audit and rollback. The platform
must stay rebuildable when the cluster is not, and one team must not be able to deploy into, or
read, another team's namespaces.

## Decision

**Delivery**

- **Argo CD,** installed and pinned through a `HelmChart` object; UI behind the gateway and the
  edge, internal-only; TLS at the edge (`server.insecure`). Dex is disabled: the platform's OIDC
  issuer is the only broker ([0018](0018-one-oidc-issuer.md)).
- **One central GitOps repository,** separate from source repositories: deploy rights are not
  code rights, CI tag bumps do not pollute source history or trigger CI loops, and Argo CD's
  read credential cannot read source code. Layout `apps/<service>/base` + `overlays/<env>`;
  **environments are directories**, so promotion is a reviewable diff instead of merges between
  environment branches. A root Application per tenant watches `applications/`; adding an
  environment is adding a file.
- **The gate is the CI bump, not the Sync button.** CI builds and pushes the image; a manual
  `bump-<env>` job commits the new tag to the GitOps repository; automated sync applies it.
  Reasons: a manual Sync gate keeps applications permanently OutOfSync, which hides real drift;
  Git stays the desired state; rollback is `git revert`; future approvals live in merge
  requests.
- **`prune` and `selfHeal` start off.** Automation only applies Git changes.
- **Argo CD never deploys the platform itself:** the platform must be rebuildable while the
  cluster is down.
- **Images:** tags carry the environment prefix and commit SHA; promotion retags the same digest
  (never rebuilds) and verifies the digests match; branch-environment images never enter the
  promotion chain.
- **The bump credential** can only write the GitOps repository and is a protected CI variable
  (unprotected branches cannot read it). "Can run the protected pipeline" therefore means "can
  change that environment's declaration", which is why fork merge-request pipelines stay off
  ([0019](0019-ci-runner-on-the-host.md)).
- **Local admin is disabled after SSO administrators are proven**
  ([0009](0009-guarded-irreversible-changes.md)); flipping it back is the documented break-glass.
  The admin password hash is never put into secrets: bcrypt salts differ on every render, so the
  manifest would change on every converge and restart the server. Read the generated initial
  password instead.

**Tenancy**

- **One AppProject per tenant, derived from the tenant's root Application name** (no second
  list): sources = the tenant's GitOps repository only; destinations = `<tenant>-*` namespaces;
  cluster-scoped kinds = Namespace only.
- **Root Applications live in a platform-owned project** that may only create Applications in
  the `argocd` namespace. Write access to that namespace would let a tenant edit everyone's
  subscriptions.
- **The `default` project is locked:** empty sources and destinations and an *explicit* empty
  cluster-resource whitelist (Argo CD's built-in default carries `*/*`, and applying a manifest
  does not remove undeclared fields). Otherwise `project: default` bypasses every boundary — the
  classic multi-tenant escape.
- **RBAC:** default role read-only; a per-tenant syncer role (read-only plus sync on
  `<tenant>/*`); administrators separate. Grant and revoke commands edit the declaration in place
  without a YAML round trip (which would drop the comments), refuse to remove the last
  administrator, and expect the user to have signed in once (emails match literally).
- **Orphaned-resource warnings stay off:** Secrets generated by External Secrets belong to no
  Application and would flood the view.
- **Rollout order:** create projects → move child Applications → lock `default`. Skipping a step
  shows up as "project not found / not permitted".
- **Names:** Application `<tenant>-<component>-<env>`, namespace `<tenant>-<env>`; length budgets
  for each part keep every composed name below the 63-character limit, so silent truncation
  never happens.

## Consequences

- Every deployment decision is a commit; rollback is the standard Git operation.
- Accepted cost: CI holds a write credential to the GitOps repository.
- Accepted cost: without `prune`, hash-suffixed generated ConfigMaps accumulate and keep the
  application OutOfSync; without `selfHeal`, something Argo CD newly recognises (for example
  after an exclusion change) is detected but not applied until a manual sync — while
  `.status.operationState` still shows the *previous* successful sync
  ([0022](0022-reported-success-did-nothing.md)).
- Accepted cost: widening one tenant (another namespace pattern, more cluster kinds) needs
  template support for that tenant; it never means unlocking `default`.
- Chart pitfall: some components cannot be switched off in some chart versions, and a values
  key that does not exist is silently ignored — verify against the chart templates.

## Alternatives considered

- **Manifests in each source repository (`deploy/`):** couples deploy and code permissions; CI
  write-backs cause loops.
- **A branch or repository per environment:** promotion by merge or cherry-pick drifts.
- **The gate on the Sync button:** see above.
- **Flux:** a fine choice; Argo CD's UI, SSO and per-project RBAC fit many small teams sharing
  one cluster better.
- **Tenant prefixes on a shared project:** relies on naming discipline instead of enforcement.

## Revisit when

- A tenant needs its own write boundary: move its directory to a repository of its own;
  repository credentials are already a list.
- OutOfSync noise is gone: consider `prune` and `selfHeal`.
- Test or production environments need approvals: decide separately whether they keep the bump
  model.
- Developer self-service (tenants creating their own projects) becomes a requirement — still an
  open question.
